# Coder

Coder is a project by Rubic, developed by Elijah Shepherd.

Coder is the central home for the Coder ecosystem: a local, open-source place for AI agents that help with computer work, coding tasks, and complex projects. It collects the ideas, documentation, and subprojects that make up Coder so there is one clear place to understand what has been made and where each part lives.

Coder is not only one app, one interface, or one release. It is the umbrella for tools that bring capable AI agents closer to a user's own computer, files, models, providers, and workflow while keeping the user in control.

## What Coder is

Coder exists to make agentic computer work feel understandable, inspectable, and useful. The project is built around the idea that an AI agent should be able to help with real tasks, not only answer questions. A Coder subproject may focus on planning, code work, project understanding, file-oriented workflows, command-oriented workflows, or other forms of computer assistance.

The important idea is control. Coder is meant to give users a clear place to bring their own work, choose the tools and models that fit them, and understand how each Coder project connects to the rest of the ecosystem.

This repository is the center of that map. It explains the project purpose, stores stable documentation, and points to every official Coder subproject.

## What this repository is for

Use this repository to find:

- The high-level explanation of Coder.
- The stable project principles behind Coder.
- The official list of Coder subprojects.
- Links to subproject repositories and their changing documentation.
- Shared information that should not belong to only one app or tool.

Subproject repositories should own their own installation steps, current feature lists, release notes, screenshots, and implementation details. Those details can change quickly. This central repository should stay focused on the deeper explanation and the long-term project map.

## What Coder is not

Coder is not limited to one provider, one model, one interface, or one release path. It is also not meant to be a place where changing feature lists are frozen forever.

Coder should stay clear about the difference between:

- The ecosystem, which is explained here.
- The subprojects, which live in their own repositories.
- The release-specific details, which belong with each subproject.

## Repository policy

This repository should stay stable, readable, and high-level. It should explain the Coder ecosystem without depending on one temporary version, one changing feature list, or one implementation detail.

When a new official Coder project exists, add it to the subproject map. When a specific app or tool changes, update that subproject's own repository instead of turning this repository into release documentation.
