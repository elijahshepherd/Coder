# What Coder is

Coder is a Rubic project developed by Elijah Shepherd. It is a home for local AI agent tools that help people use their own computers for coding work and complex project tasks.

At the ecosystem level, Coder is not a single screen or a single product shape. It is a direction: make AI agents useful on real computers while keeping the user close to the work, the files, the model choices, and the decisions.

## The core idea

A useful coding agent should do more than produce text. It should help a person reason through a project, understand what exists, make careful changes when allowed, explain tradeoffs, and carry a task across multiple steps. Complex projects are rarely solved by one answer. They need context, structure, follow-through, and a clear record of what changed.

Coder exists to support that kind of work.

The project is built around a simple belief: agentic computer work should be local, inspectable, and user-directed. The user should understand what a Coder tool is doing, where the source lives, which subproject owns which behavior, and where to find deeper documentation.

## Why a central repository exists

As Coder grows, different tools can serve different parts of the workflow. A desktop app, a command line tool, a helper library, or another interface may all be part of the same project family, but each one should not have to explain the entire Coder idea from scratch.

This repository is the central place for that explanation.

It answers questions like:

- What is Coder trying to make possible?
- Which official Coder projects exist?
- Where should someone go to find a subproject?
- Which documentation is stable across the ecosystem?
- Which details should live in a subproject because they change over time?

## Local agent work

Coder is centered on local agent work. That means the user's computer, files, development environment, and chosen tools matter. Instead of treating AI as a distant chat box, Coder projects are meant to bring AI assistance closer to real work.

A local agent workflow can help with things such as understanding a project, planning a change, editing code, reviewing results, or assisting with computer tasks. The exact capabilities depend on the subproject and its current implementation, so this central repository avoids listing temporary feature details.

The stable principle is that local work should remain visible and controlled by the user.

## Model and provider freedom

Coder should not be defined by one AI provider. The ecosystem should be able to support different models and providers over time so users can choose what fits their needs, cost, speed, privacy expectations, and workflow.

Provider details can change. The deeper Coder idea should not.

## Complex projects

Coder is especially aimed at work that has more than one step. Complex projects need planning, context, review, and correction. They often involve many files, unclear requirements, changing goals, and decisions that need to be explained.

Coder projects should help users move through that complexity without hiding what is happening. The agent should support the user, not replace the user's judgment.

## What should stay stable

This central explanation should stay stable even as subprojects change:

- Coder is a Rubic project developed by Elijah Shepherd.
- Coder is the umbrella for local AI agent tools.
- Coder focuses on computer work, coding tasks, and complex projects.
- Coder should keep users in control of decisions and workflows.
- Coder subprojects should link back to this central project map.

For current implementation details, use the subproject repository that owns the work.
