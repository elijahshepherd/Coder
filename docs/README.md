# Coder documentation

This folder holds stable documentation for the Coder ecosystem.

Coder documentation should explain the project clearly without locking the central repository to one app version, one provider list, one temporary release, or one changing interface. If a detail belongs to a specific subproject, keep it in that subproject's repository and link to it from here.

## Read these first

- [What Coder is](what-is-coder.md)
- [Ecosystem and project map](ecosystem.md)
- [Project principles](project-principles.md)

## What belongs here

Put documentation here when it applies to Coder as a whole:

- The reason Coder exists.
- The language used to explain Coder.
- Shared project principles.
- The relationship between the central repository and subprojects.
- Stable guidance for how new Coder projects should be listed.

## What belongs in subproject repositories

Keep changing or implementation-specific details in the subproject that owns them:

- Installation instructions.
- Release notes.
- Exact feature lists.
- Screenshots and UI walkthroughs.
- Provider setup details.
- Build commands.
- Architecture details that only apply to one implementation.

The central repository should help people locate those details, not duplicate them.
